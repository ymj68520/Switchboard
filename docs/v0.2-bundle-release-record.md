## Decisions applied by this release

1. **Single merged GitHub Release, v0.1 topology.** The released products ship
   as one GitHub Release (one tag, one asset per released adapter). The
   repository tag convention remains the family-level `vMAJOR.MINOR`
   (`v0.2`), recorded in the v0.1 bundle release record. `phase-model`
   (Codex) has no v0.2.0 program and no authorized release change: it remains
   at **0.0.1** exactly as published in v0.1, and no new asset is uploaded for
   it.
2. **Checksums follow the v0.1 precedent:** digests are recorded here, in the
   annotated tag message, and in the release notes; no separate SHA256SUMS
   asset is published.
3. **Release-gate repairs (recorded transparently).** Reproducing the frozen
   Claude gate on the required Node 24 runtime (the frozen 2969/3/1
   classification was produced where the Node-gated MCP bootstrap spawn tests
   skip their assertions) surfaced leftover debug `console.log` prints on
   store failure/migration paths (`migration-runner`, `assertSchemaState`,
   migrations 025/026), a missing beyond-support fence in
   `inspectSchemaState` (a store with `user_version` > 26 crashed with
   INTERNAL_ERROR instead of the contract `STORE_SCHEMA_TOO_NEW`), a stale
   too-new-store fixture (literals 14/24 → 27/27), and a bootstrap tool-surface
   assertion still pinned to the Phase-7 18-tool list (now asserted against
   the source-declared 40-tool registry). The debug prints violated the frozen
   protocol-pure-stdout invariant on every path; the fence restores the
   documented fail-closed contract (§19: old processes refuse newer stores).
   No architecture, schema, protocol, or tool-surface change is involved.

## Persistence / migration boundary

- Claude: store schema upgrades automatically to **26** (pre-migration
  backups); no reverse automatic downgrade; older plugin processes fail
  closed against a schema-26 store. Historical Directive v1/v2/v3 remain
  readable and hash-stable; new Directives use v4.
- OpenCode: version-fenced durable document store — newer-writer stores are
  refused (`store_version_unsupported`), older stores fail closed rather than
  auto-repair; pre-cutover v0.1 handoffs recover through the documented
  legacy path; new Final Approvals always produce the supervised_v0_2
  protocol.
