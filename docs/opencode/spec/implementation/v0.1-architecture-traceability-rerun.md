## Method

1. The frozen architecture and protocol v0.13 were re-read at every section where R1/R2 could have changed the disposition; the frozen architecture was verified byte-unmodified against git.
2. The original traceability matrix is the comparison baseline. For unchanged requirements the current evidence was re-confirmed (source still present, tests still green); for B-A–B-D and every affected invariant the old implementation evidence was REPLACED with post-remediation evidence found in current source and current tests — this document is not the old document with four cells changed.
3. Implementation reality was established by direct source inspection of the current tree (`src/context/*` assembler subsystem, `src/memory/store.ts` + `document.ts` + `durable-store.ts`, `src/core/capabilities.ts`, `src/core/controller.ts`, `src/transaction/types.ts`, `src/tools/contracts.ts`, `src/index.ts`, `src/handoff/assemble.ts`) with `file:line` citations, plus targeted sweeps (mutation paths, read-only context, forbidden tools, truncation, stubs).
4. All verification was re-run with true producer exit codes, smokes in isolation (see Verification Results): scoped typecheck/lint/test/build first-run green; three live smokes; root aggregate.
5. Every requirement received exactly one primary disposition from the frozen vocabulary (`PASS`, `PASS_WITH_INTERPRETATION`, `DEFERRED_NON_BLOCKING`, `OUT_OF_SCOPE_BY_ARCHITECTURE`, `UNVERIFIED`, `RELEASE_BLOCKER`) and the strongest available evidence level (`S` source, `T` deterministic test, `C` crash/concurrency process proof, `L` real OpenCode live-runtime proof). No evidence level was upgraded by resemblance.

Citations are `file:line` inside `adapters/opencode/` unless prefixed `repo:`. Line numbers refer to the current worktree.

## Original Blocker Re-disposition

### B-A — Conflict resolution lifecycle — original: RELEASE_BLOCKER → **current: PASS** (S+T+C+L-refusal)

- **Original failure:** conflicts could be raised (severity model-chosen) in every design stage, but no code path in any stage ever set a conflict to `resolved`; open blocking conflicts blocked finalization AND intersecting commits permanently.
- **Remediation implemented (R1):** closed `resolve_conflict` change (design_checkpoint/amendment proposals, architecture/detail only) — the ONLY `open → resolved` path; Harness-derived resolution bindings; `ultraplan_resolve_conflict` forbidden as a standalone tool (contracts.ts:364-366).
- **Current source proof:** staging verifies against STAGED state — `amend_decision` binds an exact resulting DecisionRef that this transaction creates AND the conflict names; `amend_architecture` binds the exact resulting ARCH@n+1 this transaction creates; `revise_proposal` binds the carrying proposal's own exact ref; one resolution per conflict per proposal; resolutions immutable (store.ts:3598-3693).
- **Current test proof:** r1-blocker-remediation.test.ts resolution lifecycle + binding refusals + §42 self-block + §49 durable fail-closed; all green in 634/634.
