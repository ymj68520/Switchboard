Every row records: the failure window, the expected canonical durable state, the deterministic recovery action, the duplicate-prevention invariant, and the enforcing test. All recovery decisions derive from the durable Store (Phase 8 §35) — never from conversation text, in-memory flags, child-session existence, or runtime counters.

## Durable-truth audit (Phase 8 §35)

For every row above, the recovery input is exclusively: the durable document (`plan-store.json` through `DurablePlanStore`), its indexes, and records created inside transactions. No recovery path reads conversation history, session existence, in-memory controller fields, or wall-clock ordering to decide ownership or progress. The supervisor's per-turn context is rebuilt from the Store every turn (§68).

## Response-loss idempotency (Phase 8 §37)

Directive issue, Report submit, Assessment/Commit, Reconciliation record, Replan transition, and Completion each carry a natural idempotency identity (handoff key, directive revision, attempt, assessment hash, commit tuple, gate, issue key). Retrying after a lost response resolves the existing durable artifact; authoritative artifacts are never duplicated. Enforcing tests are cited per row.

## Budget-exhaustion neutrality (Phase 8 §38)

`budget_exhausted` and repeated-`blocked_runtime`/`awaiting_supervisor` yields mutate NO lifecycle, Stage, Window, candidateRevision, or acceptedHead — the run stays `active` and resumable with a fresh budget (§29). Enforcing tests: `execution-production-handoff.test.ts` (yield neutrality), `execution-production-e2e.test.ts` §80 (tiny budget → yield → same-session resume completes).

## No unbounded loops (Phase 8 §39)

Automatic loops and their bounds: supervisor read rounds per turn (`maxSupervisorReadOpsPerTurn`), supervisor turns per pump (`maxSupervisorTurnsPerPump`), worker dispatches per pump (`maxWorkerDispatchesPerPump`), consecutive supervisor protocol failures before yield (`maxConsecutiveSupervisorProtocolFailures`), bounded conflict-resolver recursion, no automatic verification retry, no worker replay (interrupted attempts become indeterminate, never re-dispatched). Enforcing tests: budget tests in `execution-production-handoff.test.ts`; orchestrator bounds in `execution-runtime-orchestrator.test.ts`.
