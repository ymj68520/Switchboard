## Handoff Reliability

**Measurement (§28):** `smoke:opencode-handoff` executed **10 sequential times, isolated, same machine** (nothing else ran):

```text
run 1  PASS 16/16  230 s        run 6  FAIL 3/5   276 s
run 2  PASS 16/16  141 s        run 7  FAIL 3/5   273 s
run 3  PASS 16/16   44 s        run 8  FAIL 3/5   278 s
run 4  PASS 16/16   49 s        run 9  FAIL 3/5   271 s
run 5  PASS 16/16  215 s        run 10 FAIL 3/5   280 s
```

**Failure analysis:** runs 6–10 failed at the SAME setup check ("/ultra-plan creates PLAN-001 — run not observed"): the command POST was accepted (200), the server was healthy (session creation, config, and tool-ids checks all passed), and the session history never showed a planning run because **the model never invoked `ultraplan_start` — zero occurrences of the tool call in any failing log, zero server-side errors**. Five consecutive passes then five consecutive identical failures indicates a gateway/model state shift mid-series (free-tier `opencode/*` gateway), not a 50% random flake. The restart-readiness `fetch failed` mode seen twice in earlier phases did NOT occur in 10 runs (0/10).

**Classification (§29): environmental — model-provider non-cooperation on the smoke's SETUP leg** (the harness asks a real free-tier model to invoke a tool on demand). Explicitly NOT: a smoke harness race around the handoff itself, an OpenCode server readiness race (the failing runs' servers served every non-model request), a plugin startup race, or an Ultra Plan recovery race (crash windows A–F prove exactly-once recovery at process level, DISPATCHES=1). Production behavior is unaffected: **every run that reached the handoff leg passed ALL 16 checks including the same-session proof (5/5)**, plus the exit-review re-run's 16/16.

**Explicit decision (§81/§30): YES — understood and sufficiently bounded for release**, with the distinction documented: the deterministic release gate for handoff correctness is the crash-window suite (C-level, exactly-once); the live smoke is the L-level confirmation and requires model cooperation only for its SETUP leg. Release gate policy (§49): handoff smoke must be green on the RC candidate with a DISCLOSED bounded retry — at most one retry per failed leg, first and second results both recorded with the failure classification. **Not** silent retry-until-green; unexplained handoff-leg failures (as opposed to setup-leg model non-cooperation) would be a finding, not a retry.
